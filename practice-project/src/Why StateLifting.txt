Sabse Pehle Problem Samjho: "Data Sharing Conflict"
React mein data hamesha "One-Way" (Parent to Child) flow hota hai. Agar tumhare paas do aise Child components hain jo ek dusre se connected nahi hain (siblings), aur unhe ek hi data chahiye, toh tum kya karoge?

Agar tum dono mein alag-alag useState banaoge, toh wo dono kabhi sync nahi rahenge. Ek mein change hoga toh dusre ko pata hi nahi chalega.

Real-world Analogy: Maan lo ek ghar mein do bhai-behen hain. Dono ko ek hi TV ka remote chahiye. Agar remote ek bhai ki pocket mein hai, toh behen use access nahi kar sakti. Remote ko "lift" karke Table (Common Parent) par rakhna padega, jahan se dono use access kar sakein.

2. Solution Samjho: State Lifting Kya Hai?
State Lifting ka matlab hai—State ko wahan le jao jahan se wo dono (ya saare) related components ko "Visible" ho.
Hum state ko Child se hata kar unke Common Parent mein shift kar dete hain. Ab Parent dono ko data props ke zariye bhejta hai.

3. Explain the 3 Golden Steps
Identify: Dekho ki kaunse do components ko same state chahiye.

Lift: Un dono components ke "Common Parent" ko dhoondo. State ko wahan move karo.

Pass Down: State (value) ko neeche bhejo, aur state ko update karne wala function (setState) bhi props mein neeche bhejo.

Pro-Tips / Senior Developer Insights
Single Source of Truth: State Lifting ka sabse bada fayda ye hai ki app mein data ka ek hi "Source of Truth" hota hai. Confusion khatam ho jati hai ki actual data kaunsa hai.

The "Lifting" Limit: Agar tum state ko bahut zyada upar (e.g., App component) le jaoge, toh har choti update par pura app re-render hoga (Performance Issue). Aise mein Context API ya Redux use karna chahiye.

Don't over-lift: State ko sirf utna hi upar le jao jitna zaroori hai. Use "Nearest Common Ancestor" kehte hain.

Summary for your interview/teaching:
"State Lifting is the process of moving the state to the lowest common ancestor of the components that need it, ensuring that data flows down while changes bubble up through callback functions."
