useRef React ka ek aisa tool hai jise samajh gaye, toh tum DOM ko apni ungliyon par nacha sakte ho. Iska basic matlab hai: "Ek aisa box jisme main kuch bhi store kar sakta hoon, lekin uske badalne par React mera component re-render nahi karega."

1. Sabse Pehle Problem Samjhao: "The Re-render Trap"
React ka rule hai: Agar tum useState update karte ho, toh component re-render hota hai (yaani pura function dobara chalta hai).

Ab socho, tumhe koi aisi value track karni hai jo UI par nahi dikhni chahiye (jaise timer ki ID, ya pichli value), ya phir tumhe direct kisi HTML element (input box, div) ko control karna hai. Agar tum uske liye useState use karoge, toh har update par tumhara pura component bar-bar render hoga, jo performance ke liye bekar hai.

Real-world Analogy: useState ek "Public Notice Board" ki tarah hai—jab bhi tum kuch likhte ho, sab log (UI) use dekhne ke liye mudte hain (re-render). useRef ek "Personal Diary" hai—tum usme kuch bhi likho ya badlo, kisi ko pata nahi chalta aur koi bhi kaam rukta nahi hai.

2. Solution Samjhao: useRef Kya Hai?
useRef tumhe ek Mutable Object return karta hai jisme ek current property hoti hai. Iski do khasiyat hain:

Persistence: Component ke re-render hone par bhi iski value wahi rehti hai (lost nahi hoti).

No Re-render: Iski value update karne par React component ko re-render nahi karta.

3. Explain the 3 Golden Use Cases
Accessing DOM elements: Focus dena, scroll position control karna, ya canvas/video elements ko manipulate karna.

Storing Mutable Variables: Timers (setTimeout/setInterval IDs), previous props/state, ya koi bhi aisi value jo UI update trigger nahi karni chahiye.

Avoiding Infinite Loops: useEffect ke andar kabhi-kabhi humein state track karni padti hai bina effect ko dobara chalaye. useRef wahan kaam aata hai.
